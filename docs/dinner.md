# 绅夜食堂

入口：首页右上角「更多」菜单 → 食堂（页面标题仍为「绅夜食堂」）。它是文章功能，与漫画列表、JM 封面编号分开建模。

## 列表布局

文章采用 `LazyVerticalStaggeredGrid` 多列交错排布，按列宽和图片真实比例确定卡片高度。
封面按各自真实比例完整展示，标题最多三行并显示日期；图片加载动画、图床回退与缓存继续共用文章管线。
已知图片比例按 URL 保存在 `DinnerViewModel`，图片自身仍保留 saveable 比例；文章返回和条目离屏再出现时
使用已知高度，不先重置为默认比例。不保存 painter 或位图。

列表位置使用全局 `ui/models/ListPositionMemory` 的 `dinner` 键。`StaggeredListPositionMemory` 通过框架 Saver
保存/恢复各列的索引与偏移；`GlassCaptureHost` 显式转发记忆容器，独立 ComposeView 销毁重建也能恢复。
只缓存整数位置数据，不持有滚动状态、View 或布局对象。封面与标题都能进入正文，封面加载中或失败时也可点击。

列数沿用设置中的「首页」列数：1–6 为固定列数，0 为自适应。食堂和漫画网格共用
`comicGridMinCellSize`，手机最小 118dp、平板 160dp；左右留白与列间距均为 12dp。
加载、失败重试及列表结束提示横跨全部列。到达底部自动请求下一页，不再显示「加载更多文章」按钮。
新一页必须完成布局后才会再次判断；加载中不重复请求，错误时停止自动加载并保留重试按钮。
内容未铺满屏幕或整页被过滤为空时继续取后续页，直到可滚动、出错或到达服务端末页。

## 数据与分页

- 对照官方 2.1.8：`blogs?page=N&blog_type=dinner`，每页 12 篇，原始总量字段为 `count`；详情是 `blog?id=N`，正文位于 `info.content`。
- `network/EmbeddedDinnerApi` 复用活动 SDK 客户端。请求使用 SDK 占位 host，由既有域名拦截器选择固定域名；沿用 DoH、会话、签名、重试与响应解压/解密，不新增 HTTP 客户端。
- 列表展示日期和文章图片，不单独展示上传者。详情顶部也不把 `username` / `nickname` 当成作者；正文中的署名正常保留。失败保留已有条目，重试失败页；快速切换文章时用代次保护，旧响应不能覆盖新文章。
- 取消正文作者白名单。缺少署名、作者不在旧七人名单中、列表缺少正文，都不作为广告证据；不使用上传者、日期、`gid` 或是否含漫画传送门判断。正文署名按原样渲染。
- 过滤依据是明确推广文案或已确认推广链接，任一命中即拦截；有正常漫画内容、已知作者署名也不能豁免夹带的广告。文案包括「风月 AI」「注册 VIP」「cos app 下载落地页」、明确领券入口、填写 `R18COMIC` 注册推广码，以及「购买链接」配合「心动就赶紧下单」的引导，兼容繁体、大小写、全角、空格及 HTML 内联拆分。单独出现「VIP」「充值」「优惠券」不拦截。
- 2026-10-20 实拉全部 1368 篇列表正文、抽查 57 篇详情，确认推广目标包括 `fengyue.ai`、`cos-sdg.org`、`789free.fun`、`u.jd.com`、`taoquan.taobao.com`、`dp.toys` 及已确认的游戏推广入口。匹配 URL 的实际 host 边界；短链平台仅拦截已确认的具体路径，不因有短链、外链或归因参数一律过滤。Bangumi、旧博客、普通漫画/文章链接和官方 App 说明继续保留。完整域名与路径规则集中在 `ArticlePromotionFilter`。
- 列表先检查自带 `content` 和 `game_url`；普通文章与明确广告无需补查。只有「下载链接」「购买链接」「立即体验」等尚未确认的导流提示，才请求该篇 `blog` 核对 HTML 链接；补查限时 3 秒，失败/超时保留卡片、不缓存失败，取消继续向上传递。
- 补查成功的结果在仓库内缓存 10 分钟、最多 128 条；列表正文或 `game_url` 变化即失效。详情打开始终重新请求并复检完整正文及链接，不复用列表放行结果；确认推广时从当前列表移除条目。脚本、样式、图片属性不作为文案或跳转链接，不追踪外链重定向。
- 过滤不改服务端页码、`count` 或原始条数；整页被过滤为空仍根据原始页继续加载。新推广域名和无明确导流特征的软文仍需补充证据与规则，不能将未知内容默认当广告。

## 阅读与跳转

HTML 通过 Jsoup 解析为原生 Compose 文本、标题、列表、引用、图片、代码与可横向滚动表格。保留实体、文字样式和源顺序；不运行脚本、网页样式或嵌入网页。正文参考 [PilcrowMD](https://github.com/pilcrowmd/pilcrow) 的原生阅读思路，采用衬线字体、宽松行距和阅读宽度限制，不引入其编辑器或文件操作。

JM 编码、`album/编号` / `photo/编号`、数字传送门及 `blog/编号` 都可跳转，包含作者只写文字、没有创建超链接的情形。识别跨 span 进行，保留原有文字样式。解析结果用 `jm://comic/编号` / `jm://article/编号` 表达，L1 导航分别进入现有漫画详情或文章详情；其余 HTTP(S) 链接交给外部浏览器。链接包裹的漫画图片同样保留跳转目标。

## 图片

- 保留文章图片完整路径、查询参数与实际宽高比；普通图片支持点开放大、缩放和失败重试。
- 使用 `CoverImageLoaderHolder` 的 DoH、连接池和缓存预算；JM 图床图片沿用阅读器/封面的 `JmImageHostHealth` 测速与健康状态，按顺序回退镜像，不并发竞速每一张图片。
- 内嵌标准 JM 封面共用 `jm-cover-{id}` 缓存身份；其他文章图片按原始 URL 缓存，镜像回退不会重复生成逻辑缓存身份。外站图片不改写到 JM 图床。
- 图片和页面加载复用 `ui/components/ReimuLoading.kt` 的阅读器 GIF。该组件从阅读器目录提升为公共组件，阅读器、文章与通知共同引用它，避免复制动画实现。

## 验证

默认执行 `:app:testDebugUnitTest` 与 `:app:compileDebugAndroidTestKotlin`。单测覆盖协议、图文顺序、站内链接、推广过滤后的分页、失败重试、迟到响应和共享 CDN/缓存行为。`AdaptiveComicGridTest` 核对普通网格与瀑布流在屏宽、密度、手机/平板及固定列数下的列宽一致性。
`DinnerGridTest` 提供不同封面比例的交错排布、列数改变、整行页尾与封面点击的合成 UI 场景。
`DinnerNavigationAndPagingTest` 覆盖 Glass 销毁重建后的多列位置、封面导航、触底自动加载、防重入及错误重试。
`StaggeredListPositionMemoryTest` 检查框架 Saver 各列偏移与索引的保存/恢复及清理隔离；过滤测试覆盖旧文、未知作者、推广文案、已确认链接、短链边界、夹带广告、按需补查/缓存/失败重试与取消，保留 2026-01-21 实拉署名片段作为正常正文回归样本。
`DinnerArticleRenderingTest` 提供原生排版与失败重试的插桩覆盖，按项目真机测试约定按需执行；编译通过不代表已在真机运行通过。
